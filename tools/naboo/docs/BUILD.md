## Engine build

```
cmake -S naboo_src -B build_naboo -G "Visual Studio 17 2022" -A x64 -DCMAKE_BUILD_TYPE=RelWithDebInfo
      -DBuildMPRend2=ON -DBuildMPRdVulkan=ON -DBuildPortableVersion=ON -DBuildDiscordRichPresence=OFF -DBuildSymbolServer=OFF
      -DFETCHCONTENT_SOURCE_DIR_OPENALSOFT=<build_naboo>\_src\openalsoft-src -DFETCHCONTENT_FULLY_DISCONNECTED=ON
cmake --build build_naboo --config RelWithDebInfo -- -m
```

* The project normally downloads OpenAL Soft at configure time (`FetchContent`). To avoid any download, the source
  tree already fetched by the other build (`build_x64\_deps\openalsoft-src`) was **copied** into
  `build_naboo\_src\` and CMake was pointed at the copy.
* Result: configure and build succeeded with no errors (log `build_naboo\build1.log`). Outputs in
  `build_naboo\RelWithDebInfo\`: `taystjk.x86_64.exe`, `taystjkded.x86_64.exe`, `rd-vulkant_x86_64.dll`,
  `rd-taystjk_x86_64.dll`, `rd-rend2t_x86_64.dll`, `jampgamex86_64.dll`, `cgamex86_64.dll`, `uix86_64.dll`,
  `OpenALSoft.x86_64.dll`.
* Deploy = copy those into `devgame_naboo\` (executables and renderer DLLs in the root, the three game DLLs in
  `devgame_naboo\taystjk\`), plus `naboo_src\lib\SDL2\bin\x64\SDL2.x86_64.dll`.
* Engine changes on `naboo-theed` so far: one local commit, `d555f9291` (cooked-world pass in rd-vulkan, see `RENDERER.md`). Not pushed.
* Rebuild of only the renderer: `cmake --build build_naboo --config RelWithDebInfo --target rd-vulkant_x86_64`.
* The Vulkan renderer DLL is `rd-vulkant_x86_64.dll`, so the client needs `+set cl_renderer rd-vulkant` (with `rd-vulkan` it silently falls back to the OpenGL renderer).

## Running

Dedicated server (as used for the tests):

```
devgame_naboo\taystjkded.x86_64.exe +set fs_basepath "<GameData>" +set fs_homepath "<devgame_naboo>" +set fs_game taystjk
    +set dedicated 1 +set net_port 29180 +exec naboo_server.cfg +devmap <map> +exec naboo_bots.cfg
```

`naboo_server.cfg` was written for this work (no passwords, master servers blank so the server is not advertised,
`sv_fps 40`, sabers only, cheats on). Port 29180 keeps it apart from the other session's 29170.

Run so far: the server was started on the stock map `mp/ffa1` (loads, runs, quits cleanly) and on the prototype
collision map (see `BENCHMARKS.md`). **Korriban was not run from this directory.**

## Shader compilation (needed from the renderer step on)

The renderer's SPIR-V is checked in as C arrays and regenerated by `codemp\rd-vulkan\shaders\compile.bat`, which
expects `%VULKAN_SDK%\Bin\glslangValidator.exe` and a Visual Studio 2019 path. No Vulkan SDK is installed, but
`E:\RenderDoc\plugins\spirv\glslangValidator.exe` (glslang 15.3.0) exists. Test done: `color.vert`, `color.frag`
and `bloom.frag` compiled with it to 872, 904 and 3,488 bytes, exactly the sizes of the checked-in arrays, and a
`gen_vert.tmpl` variant compiled without errors. So new shaders can be compiled here without a download; the batch
file will need its two hard-coded paths overridden. Byte-for-byte equality with the checked-in data and a run of
the regenerated shaders in the game were not checked.
